# Personal Growth Report

把一段时间内「个人」大类的记录（个人项目、个人产品、兴趣开发）整理成一份中文 Markdown 个人成长记录。**本 SKILL 是结构与规则的唯一权威**。

这份记录的目的不是汇报，而是帮「我」复盘：这段时间自己做了什么，有没有更好的做法，还能往哪延伸，以及**哪些知识必须自己补上**。很多代码是 AI 写的，但我不能对它一无所知：至少要看得懂、改得动、出了问题能排查。

## Input

调用方提供：

- `title`：标题（如 `个人成长月记 - 2026-09`）。
- `type`：`week` / `month` / `year`。
- `report_type_label`：`周报` / `月报` / `年报`。
- `platform_count` / `record_count`：本阶段个人平台数、记录数。
- `platforms`：本阶段涉及的个人平台名列表。
- `source`：按平台分组的原始记录（`## 平台名`，每条 `- {date}: {content}`）。
- `previous_summary`（可选）：上一期成长记录的「概览」段。**未提供时不得出现"相比上期"之类的措辞。**
- `personal_profile`（可选）：`<personal_profile>` 标签里的个人能力档案，记录我各项技术的掌握程度、依据和短板。**未提供时**，「建议补的知识」只根据记录本身推断，并在该节开头写一句「本期未参考能力档案」。

## 掌握程度等级（与能力档案、问卷共用）

| 等级 | 含义 |
| --- | --- |
| L0 | 没接触过 |
| L1 | 能大致看懂 AI 写的代码在干什么 |
| L2 | 能在 AI 或文档指引下修改、调通 |
| L3 | 能不依赖 AI 独立实现常见需求 |
| L4 | 能排查疑难问题、做技术选型和设计取舍 |
| L5 | 能讲给别人听，有自己的沉淀和最佳实践 |

## Output

**直接输出 Markdown，不要用 ``` 包裹整篇**。结构按以下顺序：

```markdown
# {title}

## 🏝️ 概览

{80-180 字：这段时间自己主要在做什么、花在哪个项目上最多、整体推进到什么程度。}

## 🧩 这段时间做了什么

### {平台名称}

- **{动词开头}**{合并后的产出，每条一句话，3-6 条；PR 编号、commit hash 等标识保留原样}

## 💡 更好的做法

- **{具体的某件事}**：{当时怎么做的 → 更好的处理办法可能是什么 → 为什么更好。2-4 条，必须对应记录里真实的做法，不要泛泛而谈}

## 🌿 可以延伸的方向

- **{方向}**：{基于已做的东西，还可以往哪里扩展（功能、技术深度、产品化、复用到工作中等），2-4 条}

## 📖 建议补的知识

{先用 1-2 句说明判断依据：这段时间在哪件事上投入最多、用到了哪些技术，对照能力档案里我原本擅长什么（比如擅长 PHP 后端，但这次主要在用 React 做 App）。}

| 知识点 | 为什么要学 | 目标程度 | 怎么验证学会了 |
| --- | --- | --- | --- |
| {具体到可学习的颗粒度，如「React Hooks 的依赖数组与闭包陷阱」，不要只写「React」} | {结合这段时间的具体场景} | {L2-L4} | {一个可操作的检验动作，如「不看 AI 输出，手写一个带防抖搜索的列表组件」} |

{3-6 行；优先挑「这段时间高频使用、但档案里等级低或没有记录」的技术。}

## 📝 能力自评问卷

> 填写说明：选择题把 `[ ]` 改成 `[x]`；问答题直接写在「回答：」后面。填完把本节整段交回，用于更新个人能力档案。
>
> 问卷周期：{title}

### 一、{技术名}（{这段时间用它做了什么，一句话}）

**Q1. 你现在对 {技术名} 的整体掌握程度？**

- [ ] L0 没接触过
- [ ] L1 能大致看懂 AI 写的代码在干什么
- [ ] L2 能在 AI 或文档指引下修改、调通
- [ ] L3 能不依赖 AI 独立实现常见需求
- [ ] L4 能排查疑难问题、做技术选型和设计取舍
- [ ] L5 能讲给别人听，有自己的沉淀

**Q2. 下面这些知识点，你能不看资料讲清楚的有哪些？（多选）**

- [ ] {知识点 1}
- [ ] {知识点 2}
- [ ] {知识点 3}
- [ ] {知识点 4}

**Q3. {一道结合本期项目的具体问答题，如「项目里 xxx 这段是怎么实现的？如果让你不用 AI 重写，你会怎么拆？」}**

回答：

**Q4. 这段时间用 {技术名} 时，哪一处你是完全交给 AI、自己没看懂的？**

回答：

### 二、{下一个技术名}

{同样的 Q1-Q4 结构，题号继续递增}

### 综合

**Q{n}. 这段时间学习 / 开发上最大的卡点是什么？**

回答：

**Q{n+1}. 接下来最想优先补哪一块？打算每周投入多少时间？**

回答：

## 🌙 结束语

{1-2 句，第一人称，务实收尾。}
```

## Rules

### 结构
- 恰好一个 H1，与 `title` 完全一致，不加图标；H2 节标题和图标固定如上，不增减、不替换。
- 平台 H3 不加图标，同名平台合并，按投入从多到少排序。
- 问卷里的「技术」要按**这段时间实际高频用到的技术**挑 2-4 个，每个技术一个三级小节；题号全篇连续递增（Q1、Q2 …）。
- Q2 的知识点要具体到可以自测（如「useEffect 的清理函数什么时候执行」），不要写「基础知识」「进阶用法」这类空词，每题 4-6 个选项。
- Q3 必须结合本期记录里的真实功能或代码出题，不要出教科书式的通用题。
- 问卷保持上面的 checklist 与「回答：」格式，方便交回后逐题解析。

### 内容真实性
- 「做了什么」「更好的做法」「延伸方向」只能从 `source` 推导，不编造记录外的项目、数据和经历。
- 「建议补的知识」与问卷可以做合理的专业判断（推荐学什么、学到什么程度），但**推荐理由必须挂钩到记录里的具体事情**或能力档案里的具体条目。
- 能力档案里的等级是**我的历史自评**，只用来对比「擅长什么、缺什么」，不要复述整份档案。
- 对比叙述仅当提供 `previous_summary` 时出现。

### 记录较少时的精简策略
- 当 `record_count < 3`：保留「概览 + 这段时间做了什么 + 建议补的知识 + 能力自评问卷 + 结束语」，问卷只挑 1-2 个技术；「更好的做法」「延伸方向」推不出来就省略整节。

### 防泄漏
- 正文不要提到 skill、prompt、模型、生成流程；不要写「以上是…」「希望对您有帮助」等客套话。
- 用第一人称「我」，不要写「用户」「您」。
- 「靠 AI 完成」「AI 写的代码」属于我的工作方式本身，允许出现。

### 空记录兜底
- 如果没有记录，**只输出**：

```markdown
# {title}

暂无记录。
```
